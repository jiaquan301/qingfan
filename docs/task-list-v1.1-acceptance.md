# 青番任务清单 V1.1｜产品定义与验收记录

## 核心设计判断

青番首先是专注工具，任务清单只帮助用户快速确定当前任务，开始专注，不引入项目、标签、优先级、截止日期或子任务。

- **一份任务数据**：待办、已完成共用 `Model.tasks`，`current_id` 只引用唯一一个未完成任务。当前任务在原列表中只出现一次。
- **明确三种状态**：选择当前任务、计时器运行、任务完成相互独立。勾选表示完成；点击标题表示选择；底部“开始专注”启动计时，不代表任务完成。
- **管理与专注分离**：任务窗口约 400×520 逻辑像素、最小 360×360，高度受屏幕工作区与 620px 上限约束。悬浮计时器继续使用现有的圆形完整态与迷你态。
- **长清单不改变窗口大小**：滚动区域独立；任务标题、添加入口、主按钮保留可见，已完成任务默认折叠。搜索只过滤视图，不改变任务存储顺序。
- **行为优先于视觉**：长名称截断、0 个番茄不展示、当前任务有文字标识、次要操作集中到菜单、完整计时才累计番茄数。

## 交互规则

| 操作 | 结果 |
| --- | --- |
| 回车添加 | 新任务追加到待办末尾；若尚无当前任务则选中；不重置正在运行的计时 |
| 点击任务标题 | 选择该任务；专注运行中拒绝切换并显示提示；暂停但未完成时要求确认放弃本轮 |
| 勾选待办任务 | 标记完成，移动到已完成区域；当前任务进行中拒绝并提示先暂停 |
| 标记当前任务完成 | 选中原位置的下一待办；如不存在，则选择第一个剩余待办；不自动开始下一轮 |
| 取消已完成勾选 | 恢复待办末尾，保留原番茄计数 |
| 拖动或 Alt+方向键 | 只允许待办内部排序；搜索过滤结果不参与排序 |
| 删除 | 更多菜单操作，支持 7 秒撤销；正在运行的当前任务不能删除 |
| 撤销 | 只逆转受影响任务，保留 7 秒内新增或改动的其他任务；不可擅自切换已经在运行的新专注 |
| 搜索 / Ctrl+F | 实时按任务名称匹配，待办与已完成仍区分；清空搜索不改变状态 |
| 点击底部开始专注 | 启动同一个计时器，并收起任务管理窗口；运行中打开任务清单，底部改为“返回专注” |

## 自动化验收

必须由 Ubuntu 22.04 + GTK 3 + Xvfb + D-Bus 的 CI 验证，不允许在无法启动 GTK 时跳过 GUI 测试。

1. 运行 Python 编译检查、安装脚本的 Shell 语法检查与全部单元/交互回归测试。
2. 对 5、20、50 个任务分别检查窗口宽高恒定、列表项数量及滚动区域；在 20、50 项条件下，`vadjustment.upper > page_size`。
3. 验证选择、完成/恢复、当前任务高亮、搜索、拖动、键盘排序、删除撤销以及完整番茄计数。
4. 验证运行中保护、未完成专注切换确认、任务完成后自动选择下一项、窗口切换时仍只有一份计时状态。
5. 真实 GTK 绘制截图必须包含完整悬浮时钟、100×100 迷你时钟、普通任务清单和 50 项长清单；禁止接受空白帧。
6. 对任务清单截图检查底部主按钮的实际 GTK 坐标，**整枚按钮必须位于窗口可见范围内**，不能只因自动化测试通过就忽略裁切。

## 实机验收边界

GitHub CI 可验证逻辑、GTK 控件、虚拟 X11 绘制和窗口分配，**不能替代真实 Ubuntu 22.04 GNOME 桌面操作验收**。正式使用前仍需检查 X11/Wayland 下的置顶、窗口拖动、透明合成、多屏、字体缩放、鼠标滚动/拖动与悬浮控件的点击手感。

只有自动化测试、虚拟桌面截图和本机基本交互均符合预期，才能称为完整实机验收。
